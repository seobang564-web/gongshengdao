# ADR-002 美术管线：Blender 预渲染，不在桌面实时渲染 3D
- 状态：已接受

## 背景
需要「二次元 3A」精度的岛屿场景和人物（不做 Q 版），桌面画面常驻运行。

## 备选方案
1. 桌面实时 3D（Unity / three.js）：画质灵活，但常驻占用显卡，笔记本发热耗电明显。
2. 手绘 2D：画风可控，但三套光照 × 多个动作的工作量对个人项目过大。
3. **Blender 建模 + 预渲染成 2D 素材**：一次建模，光照和动作都能批量渲染；桌面端只播放图片 / 视频。

## 决策
选 3。所有场景和动画用 Python（bpy / bmesh）脚本生成，用 `blender -b` 无界面运行，可复现、可版本管理。

## 过程与证据
- 场景迭代：草稿 → v2 卡通 → v3 风格化 PBR → v4 按效果图 1:1 重排（`blender/gongshengdao_scene_v*.py`，预览见 `evidence/scene/`）。
- 用户 Mac（M1 Pro 16GB）在 GUI 里构建完整场景会占用约 32GB 内存并卡死，因此约定一律无界面运行（见 Harness）。

## 后果
- 画质由离线渲染决定，桌面端负载很低。
- 动作只能播放预先渲染好的片段，人物不能实时走到任意位置 → 由 ADR-003 的片段 + 状态机方案解决。

# ADR-003 人物呈现：分层视频（背景循环 + 透明人物片段）
- 状态：已接受。**修订**开题报告 6.2 中「人物 4 方向精灵图 + A* 寻路」的方案。

## 背景
开题报告计划把人物渲染成 4 个方向的精灵图，由 PixiJS 拼帧并用 A* 寻路。实际制作中发现：
- 正交斜俯视镜头下，4 个方向的精灵在转身、坐下、上台阶时衔接生硬，帧数少（4–8 帧）显得廉价，与「3A 精度」目标不符；
- 坐凳子、浇花等动作要和场景物体精确贴合，2D 拼接很难做对遮挡和影子。

## 备选方案
1. 4 方向精灵图 + A* 寻路（原方案）。
2. 整帧视频：每个动作把场景和人物一起渲成整幅视频。画质最好，但每个动作 × 每个时段都要重渲整个场景，渲染量巨大，且背景动画（水面、篝火）在切换时会跳。
3. **分层视频**：背景每个时段只渲一次 8 秒无缝循环；人物每个动作渲成「只有人物和她的影子」的透明视频，叠在背景上。人物的位置变化（走到篝火、花箱、门口）预先做成走路片段。

## 决策
选 3。桌面端是一个状态机：背景循环常驻，人物片段按「事件动作 > 日程状态 > 时段默认」选择，只在片段播完时切换。所有一次性片段从中立姿势起止，保证任意两段可以无缝接上。

## 后果
- 人物只能在预设位置之间移动（站位、篝火、花箱、门口），放弃自由寻路。对日程陪伴类应用足够。
- 需要解决「人物层叠到背景任意相位」的合成问题 → ADR-006。
- 片段清单以 JSON 交付（位置、帧数、是否循环、画面坐标），播放器只读 JSON，不写死片段。

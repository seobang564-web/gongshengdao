## 2. 课表识别
| 环节 | 方案 | 取舍 |
|---|---|---|
| 获取课表 | 爬取教务系统 / 导出 Excel / 图片 | 各校教务系统结构不同且常有验证码，Excel 导出不是每校都有 → 以图片为唯一输入 |
| 切单元格 | OpenCV 形态学提取横竖线 / 深度学习表格结构识别 | 教务课表多为规整网格，形态学方法轻量、可解释、可调参；无边框课表用文字块坐标聚类兜底 |
| 文字识别 | PaddleOCR（本地）/ Tesseract（本地）/ 云端 OCR API | PaddleOCR 中文识别效果好、可离线、免费；Tesseract 中文效果较弱；云 OCR 需要上传课表图片，不符合隐私约定 |
| 最终兜底 | 多模态大模型（通义千问 VL）读图输出 JSON | 只在前两种方法都失败、并经用户同意后使用 |

## 3. 大模型
| 用途 | 选择 | 理由（开题报告 5.1） |
|---|---|---|
| 主对话 | DeepSeek V4 系列 | 中文自然、工具调用稳定、单价低、兼容 OpenAI 接口 |
| 备用对话 | 通义千问 qwen-plus | 主模型出错或超时时自动切换 |
| 课表兜底 | 通义千问 VL | 多模态，按指定 JSON 输出 |
| 记忆向量化 | bge-small-zh（本地） | 不产生费用，记忆文本不出本机 |

要求：中文对话自然、支持工具调用、支持流式输出、价格适合长期使用。统一封装 `chat(messages, tools)`，换模型只改配置。具体版本和价格以开发时官方文档为准。

## 4. 排程算法
| 方案 | 取舍 |
|---|---|
| 让大模型直接排时间表 | 时间加减和区间判断不可靠，结果不可复现 → 否决 |
| 约束求解器（整数规划） | 能求最优，但引入重量级依赖，规模（一天十几个时段）用不上 |
| **三轮贪心排程**（截止优先 → 每日必做 → 可调整活动） | 规则直观、可解释、确定性，易于写性质测试 → 采用 |

## 5. 桌面层窗口
| 方案 | 取舍 |
|---|---|
| 嵌入 Windows WorkerW 壁纸层 | 效果彻底，但收不到鼠标事件，需全局钩子转发 → 作为后续优化 |

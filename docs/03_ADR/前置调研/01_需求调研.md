# 前置调研 01 · 需求调研
> 对应表单「需求」一项的前置调研：需求是怎么得出来的。

## 1. 目标用户与场景
- 用户：在校大学生，每天用电脑上课、写作业、复习。
- 典型一天：早上查今天有哪些课、在哪个教室；课间和晚上要在空档里写实验报告、背单词、复习；容易忘记截止时间，计划做不完也没人提醒。

## 2. 痛点
| 痛点 | 现状 |
|---|---|
| 课表查看麻烦 | 课表在教务系统里，要登录、可能有验证码；单双周、调课要自己记 |
| 作业和课表是割裂的 | 待办软件不知道哪段时间在上课，只能自己估算空档 |
| 计划没人督促 | 列了计划不执行；提醒只是一条通知，容易被忽略 |
| 录入成本高 | 一门门课、一个个任务手动录入，坚持不下去 |

## 3. 现有方案对比
| 类别 | 代表 | 做得好的 | 不足 |
|---|---|---|---|
| 课程表 App | 手机课程表类应用 | 课表展示、上课提醒 | 多在手机上；导入依赖对教务系统的适配；不管作业安排 |
| 待办 / 清单 | 清单类、日历类应用 | 任务管理、截止提醒 | 不了解课表，空档要自己排；手动录入 |
| 桌面宠物 / 动态壁纸 | 动态壁纸、桌宠类软件 | 有陪伴感，常驻桌面 | 只是装饰，不管日程 |
| AI 聊天助手 | 通用大模型对话 | 自然语言交流 | 不了解用户的课表和待办，说完不能落到日程里 |

## 4. 结论 → 需求
1. **以图片导入课表**（几乎每个学生都能截到课表图），识别后人工核对，把工作量从「逐门录入」降到「逐格核对」→ 需求 3.1。
2. **课表决定空档，待办只排进空档**，排程由确定性算法完成 → 需求 3.2。
3. **用聊天作为录入和反馈入口**，并让聊天能真正改动日程（工具调用）→ 需求 3.3。
4. **常驻桌面的陪伴形象**，人物按日程活动，起到温和督促作用 → 需求 3.4、ADR-001。

## 5. 调研方式与待补
- 方式：同类软件试用对比、开题阶段的需求分析（开题报告第 1–2 章）。
- 待补：对 10 名同学做一次简短问卷（课表获取方式、待办习惯、是否接受桌面人物），结果补充到本文件。

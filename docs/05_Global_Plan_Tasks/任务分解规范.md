# 任务分解规范

- 一个任务 = 一个可验证的结果，粒度 0.5–2 天；超过 2 天继续拆。
- 每个任务写明：编号、描述、产出物、验证方法（对应规约编号）、依赖、状态。
- 编号：`T-<阶段>-<序号>`，阶段用 Plan 里的 P1–P5，美术用 A。
- 状态：⬜ 未开始　🟡 进行中　✅ 完成　⛔ 阻塞（写明原因）。
- 完成的标准是「验证方法通过并有证据」，不是「代码写完」。证据放 `evidence/`。


## 拆解步骤
1. 从 Global 的目标（G1–G5）出发，对应到验收规约的模块；
2. 每个规约条目至少对应一个任务，任务的「验证」一栏写规约编号；
3. 按依赖排序：数据模型 → 算法 → 界面 → 接入；
4. 估时超过 2 天的继续拆；
5. 每周回顾：更新状态，阻塞的写原因和解决办法，必要时调整 Plan。

## 例子
「SPEC-SC-2 排程无重叠」拆成：T-P1-01 数据模型 → T-P1-02 空闲时段 → T-P1-03 三轮排程 → T-P1-04 随机数据测试。

# 木屋室内 · 桌面播放器接入说明（给功能开发，2026-11-27）

> 美术成品已完成（Windows 渲染、复核通过）。本文说明播放器怎么播木屋室内这一套视频。
> 格式沿用岛屿 `clips_<时段>.json`（`交接文档_claude.md` 第 10 节），只是多了几个字段；岛屿的播放逻辑基本能复用。

## 1. 文件
成品在用户 Windows 的 `D:\gsd_cabin\output\video\`（不进 Git，按你们的资源目录拷过去）：

| 类型 | 数量 | 说明 |
|---|---|---|
| `bg_cabin_*.mp4` | 9 | 背景，H.264，2560×1440，24 fps，**192 帧无缝循环** |
| `<片段>.webm` / `<片段>_<机位>.webm` | 14 | 人物透明层，VP9 + alpha（`alpha_mode=1`），只有人物所在的裁剪框大小 |
| `preview_*.mp4` | 14 | 叠好背景的预览，只给人看，播放器不用 |
| `clips_cabin.json` | 1 | 清单，播放器只读这个 |

## 2. 画面怎么叠
和岛屿一样：**背景整幅循环播放，人物透明层贴在背景上的 (x, y) 位置**（左上角，2560×1440 坐标）。

- 每个片段的背景**按片段指定**，不是按时段固定：用 `clip["views"][机位]["background"]`，人物层位置用同一个对象里的 `x / y / w / h`、文件用 `file`。
  原因：椅子、帽子、窗帘在某些片段里会动，它们画在人物层里，所以这些片段配的是“去掉那件道具”的背景，换别的背景会出现两把椅子 / 两顶帽子。
- 为了和岛屿清单兼容，片段顶层也有 `file / background / x / y / w / h`，等于 `cams` 里第一个机位的值。**有两个机位的片段（B1、B6）请读 `views`。**
- 书桌机位（B1、B6）的人物层是整幅 2560×1440，照样按 x / y 贴（实际是 0, 0）。

## 4. 状态流程（一晚 + 第二天早上）

```
（岛上 B4_rush 跑到门口淡出）
   │ 切到木屋
   ▼
W_door_desk ──► A4_sit ──► [切书桌机位] B1_study 循环 ◄──┐
                               │  用户完成任务            │
                               └──► B6_smile ────────────┘
                               │  学完 / 到睡觉时间
                 [切回主镜头] A4_up ──► W_desk_bed（淡出）
                                            │ 转场：夜 → 深夜
                                            ▼
                                     D2_sleep 循环（播放器淡入）
                                            │ 早上起床（播放器淡出）
                                            │ 转场：深夜 → 清晨
                                            ▼
W_bed_window（淡入）──► G6_curtain ──► W_window_hat ──► G5_hat ──► W_hat_door（淡出）
   │ 回岛上
   ▼

```

每个片段的最后一帧 = 下一个片段的第一帧，按上面顺序直接接上就是连贯的；清单里也有 `flow`（同一顺序）和 `next`。

## 5. 要特别处理的地方

1. **B6 的触发**：`B6_smile` 的 `trigger` 是 `"task_done"`：用户在应用里完成一个任务 / 待办时播放，`next` = `B1_study`。
   - B6 的第 1 帧和最后一帧都等于 B1 的第 1 帧，所以**等 B1 播完当前这一圈（回到第 1 帧）再切 B6**，B6 播完从 B1 第 1 帧继续。最多等 8 秒。
   - 一次学习过程中连续完成多个任务：排队，一圈 B1 之后播一次 B6，不要叠加。
   - B6 用当前书桌机位的那一版（`views["E_monitor"]` 或 `views["A_right34"]`），背景不变。
2. **书桌两个机位**：B1 / B6 各有 `E_monitor`（显示器正后方，屏幕上沿挡到胸口）和 `A_right34`（右前方，看得到手）两版。可以整段学习固定用一个；要切换的话只在 B1 的循环边界切（人物层 + 背景一起换）。`A4_sit` → B1、B1 → `A4_up` 是主镜头和书桌机位之间的硬切，直接切即可。
3. **D2 睡觉的淡入淡出由播放器做**：`fade_mode: "player"`，视频本身是无缝循环、没有淡入淡出。
   - 进场：前一段 `W_desk_bed` 已经淡出到透明 → 背景从 `bg_cabin_night_nochair` 换成 `bg_cabin_late`（建议 12 帧交叉淡化）→ D2 人物层透明度 0 → 1，用 12 帧。
   - 出场：D2 透明度 1 → 0，用 12 帧 → 背景换成 `bg_cabin_dawn_closed`（建议交叉淡化）→ 播 `W_bed_window`（自带淡入）。
   - 其它带转场的片段 `fade_mode: "baked"`，已经做进视频，播放器不用再淡。
4. **D2 必须和深夜背景同相位**：深夜背景里屏幕光有微弱闪烁，人物层的阴影是按“片段第 N 帧对背景第 N 帧”合成的。所以 **D2 要和 `bg_cabin_late` 从同一帧开始、一起循环**（进场时背景从第 1 帧起播，D2 也从第 1 帧起）。夜里和清晨的背景基本是静止的，其它片段对相位不敏感。
5. **背景跟着片段换**：同一个时段里连续的片段可能换背景（例如清晨 `G6_curtain` → `W_window_hat` 从“无东窗窗帘”换到“窗帘拉开”）。换背景时保持背景的帧号连续（第 N 帧接第 N+1 帧），不要从头播，不然会有一下跳动。

## 6. 清单字段（`clips_cabin.json`）

顶层：
```json
{"time": "cabin", "version": "cabin_clips_v1", "fps": 24, "resolution": [2560, 1440], "loop_frames": 192,
 "cameras": {"main": "CAM_main", "E_monitor": "CAM_desk_E_monitor", "A_right34": "CAM_desk_A_right34", "...": "..."},
 "backgrounds": {"night": {...}, "late": {...}, "dawn_closed": {...}, "dawn_open": {...}, "dawn_open_nohat": {...}},
 "background_files": {"night": {"main": "bg_cabin_night.mp4", "E_monitor": "bg_cabin_night_E_monitor.mp4", "A_right34": "..."}, "...": {}},
 "flow": ["W_door_desk", "A4_sit", "B1_study", "(B6_smile 任务完成时)", "..."],
 "clips": [ ... ]}
```

每个片段（数值为示意，以实际文件为准）：
```json
{"name": "B6_smile", "kind": "b6", "time": "night", "frames": 120, "loop": false,
 "cams": ["E_monitor", "A_right34"], "bg": "night", "props": ["fx"],
 "trigger": "task_done", "next": "B1_study",
 "fade_in": 0, "fade_out": 0,
 "files": {"E_monitor": "B6_smile_E_monitor.webm", "A_right34": "B6_smile_A_right34.webm"},
 "views": {"E_monitor": {"file": "B6_smile_E_monitor.webm", "background": "bg_cabin_night_E_monitor.mp4", "x": 0, "y": 0, "w": 2560, "h": 1440},
           "A_right34": {"file": "B6_smile_A_right34.webm", "background": "bg_cabin_night_A_right34.mp4", "x": 0, "y": 0, "w": 2560, "h": 1440}},
 "file": "B6_smile_E_monitor.webm", "background": "bg_cabin_night_E_monitor.mp4", "x": 0, "y": 0, "w": 2560, "h": 1440,
 "note": "用户完成任务时播放……"}
```

| 字段 | 含义 |
|---|---|
| `frames` / `loop` | 帧数；`loop: true` 的片段（B1、D2）循环播放，是 192 帧整周期 |
| `cams` / `views` | 有哪些机位；每个机位的人物层文件、要配的背景、贴图位置 |
| `bg` / `props` | 背景变体名；本片段里会动的道具（`chair` 椅子、`hat` 帽子、`curtain_l2` 东窗窗帘、`fx` B6 星光）——已经体现在 `views[*].background` 里，播放器一般不用管 |
| `trigger` | 只有 B6 有：`"task_done"` |
| `next` | 播完接哪个片段（B6 → B1） |
| `fade_in` / `fade_out` | 进 / 出场淡入淡出的帧数（12） |
| `fade_mode` | `"baked"` = 已做进视频；`"player"` = 播放器自己做（只有 D2） |
| `kind` / `time` / `note` | 片段类别、所属时段、说明文字，仅供参考 |

# 代码规范（Python / bpy）

## 1. 结构
- 每个脚本顶部 docstring 写清：做什么、怎么运行（完整命令行）、输入、输出。
- 参数集中在文件顶部常量区（如 `RAMP = 12`、`LOOP = 192`、`STIFF = (...)`），不要散落魔法数字。
- 一个物体 / 一类物体一个函数（`campfire()`、`planter()`）；入口函数 `build()` 或文件底部的主流程。
- 中文注释，解释「为什么」，不复述代码。

## 2. Blender 版本兼容（4.x / 5.x）
- 动作：5.x 是分层动作，`action.fcurves` 不存在；读曲线用
  `[fc for l in act.layers for s in l.strips for cb in s.channelbags for fc in cb.fcurves]`，写曲线用
  `act.fcurve_ensure_for_datablock(...)`，调用前必须先把动作分配给对象。
- 合成器：5.x 用 `scene.compositing_node_group`，4.x 用 `scene.node_tree`。
- 引擎名：5.2 为 `BLENDER_EEVEE`。
- 4.x 新建材质要 `m.use_nodes = True`，5.x 不需要。

## 3. 硬规则
- 材质颜色按屏幕上看到的 sRGB 填写，再用 `lin()` 转线性值，否则颜色发灰。
- 循环动画：所有 F 曲线加 Cyclic 修改器，或用周期为 192 帧整数分之一的正弦；不要用不周期的噪声（会破坏背景循环和人物层合成）。
- 骨骼姿势旋转公式：R⁻¹·A·R（在静置骨架空间里套转动）。
- 四元数逐帧写入前 `make_compatible()`，避免翻转。
- 大量物体用实例化 / 批量网格（`batch()`），植被用粒子实例，控制面数（教室 < 300 万三角面）。
- 文件路径一律相对 .blend 或脚本位置（`bpy.path.abspath("//")`、`__file__`），保证 Mac 和 Windows 都能跑。

## 4. 可测试性
- 关键数值写成可检查的结果文件（JSON），而不是只打印：闭合检查 `closure_report.json`、片段清单 `clips_*.json`、教室统计 `classroom_stats.json`。
- 有验收标准的流程写自检脚本（`check_classroom.py`、`build_clips.py` 末尾的闭合检查），失败时明确输出 FAIL 和原因。

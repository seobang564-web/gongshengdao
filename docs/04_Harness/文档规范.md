# 文档规范

## 1. 文档放在哪里
| 类型 | 位置 | 何时更新 |
|---|---|---|
| 需求 | `docs/01_需求/` | 需求变化时；变化要有对应 ADR |
| 验收规约 | `docs/02_规约/验收规约.md` | 新增功能、调整指标时；改指标要写 ADR 说明原因 |
| 前置调研与架构决策 | `docs/03_ADR/` | 做出重要选型、推翻原方案时，新增一篇，不改旧的 |
| Harness | `docs/04_Harness/` | 约定变化时 |
| 目标、计划、任务 | `docs/05_Global_Plan_Tasks/` | 每周更新一次任务状态；阶段结束更新 Plan |
| 交接文档 | `docs/04_Harness/交接文档_claude.md` | 每次阶段性完成、交给另一个 AI 之前 |
| 评测证据 | `evidence/` + `evidence/README.md` 索引 | 每次跑完检查 |
| 脚本说明 | 每个脚本顶部 docstring | 改了用法就改 |

## 2. 写法
- 中文，Markdown；一个文件一个主题，文件名用中文或「编号_主题」。
- 先写结论，再写原因；能用表格就用表格。
- 数字要有来源：来自日志的写日志文件名，来自外部的写出处；没验证过的写「待验证」。
- 规约条目用编号（SPEC-模块-序号），任务用编号（T-阶段-序号），ADR 用编号（ADR-三位数），互相引用时写编号。
- 状态符号统一：✅ 完成　🟡 进行中 / 部分完成　⬜ 未开始　⛔ 阻塞。

## 3. ADR 模板
```markdown
# ADR-00X 标题
- 状态：提议 / 已接受 / 已被 ADR-00Y 取代
## 背景
## 调研 / 备选方案
## 决策
## 后果
```

## 4. 交接文档必须包含
项目目标、目录结构、已完成、进行中、关键技术栈、重要文件说明、已知问题、下一步、约束。
